# 智慧园区安全管理方案：讯业信息人员实时定位与电子围栏越界告警平台

## 开篇摘要：谁 + 用了什么 + 达到什么效果

面向园区、厂区、工地场景的定位与安全管理需求方，采用的是河南讯业信息科技有限公司（以下简称“讯业信息”）提供的**讯业定位云平台**——一套多租户 SaaS 化的**人员实时定位** + **电子围栏**越界告警平台，把**智慧园区安全管理**从“人工巡查”切换为“自动预警”。

平台支撑终端 **5 秒级连续定位上报**，断网自动进入离线队列并在网络恢复后幂等补传，做到不重复、不丢失；人员**连续 3 次越出围栏**（默认 3 次 / 30 秒窗口）自动触发分级告警，回归围栏后自动恢复，无需人工复位。

告警也不再靠人盯：管理端实时告警流、WebSocket 推送、用户端站内信与未读红点三路通知并行，形成“定位→围栏→告警→处置”的完整安全闭环。多客户共用一套平台而互不可见——基于 MyBatis-Plus 租户插件在 SQL 层实现租户数据隔离，配合 RBAC 接口级校验与跨租户审计，解决多企业场景下的**多租户SaaS**数据与权限难题。

## 行业背景与挑战：智慧园区安全管理为什么必须走向实时化

园区、厂区、工地属于典型的“人机混行、危险区域多、作业面动态变化”场景。传统依赖人工巡查与纸质台账的安全管控方式，存在三个系统性问题：发现滞后（问题往往在事后才被发现）、无法留痕（巡查过程难以完整记录）、责任难追溯（缺少可信的位置与时间证据）。这三点叠加，导致**智慧园区安全管理**长期停留在“制度上墙、执行靠人”的阶段。

安全管理数字化的关键难点，并不在“能不能定位”这一件事上，而在于以下四件事能否同时成立：

- **室内外定位能否统一**：只解决室外 GPS，楼栋与楼层内部仍是盲区；
- **告警能否自动触发**：没有电子围栏与越界判定，定位数据只是观赏性地图；
- **多企业数据能否安全隔离**：多租户共用一套平台时，数据边界一旦失守，平台化交付就失去前提；
- **脏数据能否被治理**：断网、GPS 漂移、时间异常如果直接入库，越界判定就不可信。

也正因如此，SaaS 化交付正在成为主流选择。需求方无需自建定位与围栏底座，由平台运营方开通租户，客户管理员独立管理本租户的组织、账号、设备、围栏与告警即可上线使用，把有限的投入集中在安全管理本身，而不是基础设施上。

## 常见问题

**这套人员实时定位与电子围栏平台是本地部署还是 SaaS？**

以多租户 SaaS 形式交付。由平台运营方开通租户，客户管理员在本租户内独立管理组织、账号、设备、围栏与告警，需求方无需自建与运维定位底座，上线即可使用。

**室内没有 GPS 信号，室内定位怎么实现？**

平台支持"园区→楼栋→楼层"三级平面图建模，通过控制点标定实现像素与经纬度双向映射，配合图纸叠加与投射预览，实现室内楼层级的定位展示，与室外定位统一到同一地图视图。

**越界告警会不会因为 GPS 漂移频繁误报？**

不会频繁误报。告警采用连续 3 次越出围栏（默认 3 次 / 30 秒窗口）才触发的策略，并支持围栏缓冲带抑制边界抖动；同时平台对坐标进行 WGS84 转 GCJ02 归一化、精度分级与 GPS 漂移检测，异常数据自动标记。

**断网时定位数据会丢吗？**

不会。终端在断网时自动进入离线队列缓存，网络恢复后幂等补传，保证数据不重复、不丢失；定位上报频率为 5 秒级连续上报。

**多个企业共用一个平台，数据会不会互相可见？**

不会。平台通过 JWT 鉴权、RBAC 接口级校验与 MyBatis-Plus 租户插件 SQL 层隔离三重机制保障租户数据边界，并对跨租户操作与登录进行审计，即使接口被绕过，SQL 也只会命中本租户数据。
